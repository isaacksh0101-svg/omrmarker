## 1. 종합 결론

현재 상태로는 필수기준을 모두 충족했다고 제출하기 어렵습니다.

| 구분 | 수 |
|---|---:|
| 충족 | 0 |
| 조건부 충족 | 2 |
| 부분 충족 | 6 |
| 미충족 | 0 |
| 해당 없음 | 1 |

가장 큰 심의 위험은 다음과 같습니다.

1. 개인정보 보호책임자는 학교장, 실무 담당부서는 과학정보부, 권리행사 1차 접수는 담당 교사로 정했습니다. 학교별 제출본에는 실제 학교명과 대표 전화번호를 기입해야 합니다.
2. 학생 학습 데이터는 학기 말 삭제로 정했고 학생별 완전삭제 기능도 구현했습니다. 다만 이미지·로그·복원용 `.bak` 파일의 별도 보유기간은 더 정해야 합니다.
3. 학생 기기와 교사 PC가 HTTP로 통신해 출석번호·답안·접근 토큰 등이 전송구간에서 암호화되지 않습니다.
4. 시험 시작 전 화면 이탈 규칙 안내는 기존에 있었고, 데이터 항목·저장 위치·학기 말 삭제·권리행사 안내를 같은 화면에 추가했습니다.
5. 고위험 의존성 취약점 1건(`xlsx`)이 확인됩니다.

로컬 저장 구조 자체는 장점입니다. 학생 계정·이메일·연락처·기기 식별자를 요구하지 않고, 학생 데이터는 개발자의 중앙 서버로 보내지 않으며, Gemini에도 통상 빈 시험지·정답지만 전송합니다.

## 2. 필수기준 점검

### 1-1. 개인정보가 최소한으로 수집되는가? — 부분 충족

확인된 장점:

- 학생 회원가입, 이메일, 전화번호, 주소, 학교명, 접속 IP, User-Agent를 별도 수집하지 않습니다.
- 시험 참여에는 출석번호만 필수이고 이름은 선택 항목입니다.
- 학생 세션은 순차 DB 번호 대신 무작위 접근 토큰을 사용합니다.
- 필기 획은 문항별 최대 4만 점으로 제한합니다.

남은 문제:

- 출석번호·답안·점수 외에 문항별 소요시간, 필기 획, 화면 이탈과 강제 제출 사유까지 처리하므로 각 항목의 교육상 필요성을 선정자료에 설명해야 합니다.
- 출석번호와 접근 토큰이 학생 브라우저 `localStorage`에 별도 만료 없이 남을 수 있습니다.
- 이름을 입력하지 않아도 모든 기능을 사용할 수 있다는 점을 UI와 안내서에서 더 분명히 해야 합니다.

판정 조건: 항목별 필요성 설명, 로컬 저장값 삭제 안내 또는 자동 만료, 이름 선택입력 표시를 보완하면 충족 가능.

### 1-2. 개인정보 수집·이용 목적이 기재되어 있는가? — 부분 충족

`ScoreLab 데이터 처리 및 개인정보 보호 안내서 초안`에는 시험 진행, 자동 채점, 감독, 결과 분석, 풀이 과정 확인 등 목적이 항목별로 기재되어 있습니다.

다만 현재 문서는 검토용 초안이고 학생 화면에서는 해당 목적을 볼 수 없습니다. 학교가 실제 개인정보처리자라는 전제와 학교의 적용 근거를 확정하고, 교사용 안내서 및 학생용 시험 참여 안내로 제공해야 합니다.

판정 조건: 학교용 최종본과 학생용 요약 안내를 확정·제공하면 충족 가능.

### 1-3. 수집항목과 보유기간 등이 기재되어 있는가? — 부분 충족

수집항목과 현재 저장 위치는 상세히 정리되어 있으나 실제 보유기간은 정해지지 않았습니다. 현재 동작은 대부분 교사가 삭제할 때까지 보유하는 구조입니다.

확인된 삭제 한계:

- 명단 삭제는 `roster` 행만 삭제하며 과거 응시·답안 기록의 출석번호는 남습니다.
- 일반 시험 삭제는 영구 삭제가 아니라 보관·숨김 처리입니다.
- 시험 영구 삭제 시 DB의 세션·답안·화면 이탈 기록은 연쇄 삭제되지만 업로드 이미지가 남을 수 있습니다.
- 전체 복원 전에 생성하는 `.bak-시각` DB는 자동 삭제되지 않습니다.
- 서버 로그와 브라우저 `localStorage`에 자동 보유기간이 없습니다.

판정 조건: 시험·명단·답안·필기·화면 이탈·로그·백업·이미지·브라우저 저장값별 보유기간과 파기 시점을 정하고 구현 또는 명확한 수동 절차를 제공해야 함.

### 2-1. 개인정보 안전성 확보조치가 기재되어 있는가? — 부분 충족

현재 확인되는 보호조치:

- 교사 화면 비밀번호 보호와 scrypt 해시 저장
- 12시간 만료 HttpOnly·SameSite=Lax 교사 세션 쿠키
- 학생별 무작위 접근 토큰
- Gemini API 키와 세션 비밀키의 AES-256-GCM 암호화 저장
- 교사 전용 시험·명단·백업·설정 API 인증
- 교사 로그인·세션 발급·관리 API와 교사 화면을 localhost 접속으로 제한
- 업로드 형식 및 15MB 크기 제한
- 학생 데이터의 교사 PC 로컬 저장

중대한 보완사항:

- 학생 통신이 `http://LAN-IP:4000`이며 HTTPS가 아닙니다.
- SQLite DB와 내보낸 백업 파일은 암호화되지 않습니다.
- 비밀번호 최소 길이가 4자이고 로그인 시도 횟수 제한이 없습니다.
- 최초 비밀번호 설정을 포함한 교사 인증 API는 같은 LAN의 다른 기기에서 접근할 수 없습니다.
- CORS와 Socket.IO origin이 전체 허용입니다. Socket.IO 감독 방 참여에도 별도 인증이 없습니다. 현재 이벤트에는 시험 ID만 포함되지만 인증 적용이 바람직합니다.
- Electron 서버 로그는 순환·자동 삭제되지 않습니다.
- `npm audit --omit=dev`에서 `xlsx` 직접 의존성의 high 취약점 1건이 확인됐습니다(GHSA-4r6h-8v6p-xvw6, GHSA-5pgg-2g8v-p4x9).
- 안내서에는 Gemini API 키가 평문 저장된다고 적혀 있으나 현재 코드는 암호화 저장하므로 문서가 실제 구현과 불일치합니다.

판정 조건: 전송구간 보호 방안, 비밀번호·로그인 강화, 저장·백업 보호, 로그 보유정책, 의존성 취약점 처리, 최신 구현과 일치하는 안전조치 문서를 마련해야 함.

### 3-1. 열람·정정·삭제·처리정지 절차가 안내되어 있는가? — 부분 충족

교사 화면에는 명단 수정·삭제와 시험 영구 삭제 기능이 있으나 정보주체 권리행사 절차는 완성되지 않았습니다.

- 학생·보호자는 ScoreLab을 사용한 담당 교사에게 요청하고, 필요시 과학정보부가 지원하는 것으로 정했습니다.
- 본인 또는 법정대리인 확인 방법, 결과 통지 방법과 처리기간이 정해지지 않았습니다.
- 학생 시험 시작 안내에 담당 교사에게 요청하는 방법을 추가했습니다.
- 학생 관리 화면에 명단을 유지하면서 해당 학생의 응시·답안·필기·화면 이탈 기록을 완전 삭제하는 기능을 구현했습니다.

판정 조건: 학교 담당부서·연락처, 신청 방법, 본인확인, 처리기간, 거절·제한 사유, 결과 통지 방법을 확정하고 학생별 전체 기록 조회·정정·삭제가 가능한 교사 기능 또는 운영 절차를 마련해야 함.

### 4-1. 만 14세 미만 아동 보호 절차가 마련되어 있는가? — 부분 충족

안내서에는 학교 교육활동 근거로 처리하는 기본 정보와 동의를 근거로 하는 선택 처리를 구분하고, 동의가 필요한 경우 법정대리인 확인 절차가 필요하다고 기재되어 있습니다.

시험 시작 직전 화면에는 화면 이탈 시 강제 제출 규칙이 이미 있었으며, 다음 내용을 추가했습니다.

- 처리 항목과 교육활동 목적
- 교사 PC 로컬 저장과 학기 말 삭제
- 필기 획과 화면 이탈 기록
- 열람·정정·삭제 요청을 담당 교사에게 하는 방법

또한 실제로 동의가 필요한 선택 처리를 운영할 경우 사용할 법정대리인 확인·동의 기록 보관 절차가 없습니다.

판정 조건: 아동이 이해하기 쉬운 학생용 안내 화면, 학교의 법적 근거와 보호 절차, 필요한 경우 법정대리인 동의 절차를 마련해야 함.

### 5-1. 개인정보 보호책임자 관련 정보가 안내되어 있는가? — 조건부 충족

개인정보처리자는 사용 학교, 개인정보 보호책임자는 학교장, 실무 담당부서는 과학정보부, 연락처는 학교 대표 전화번호로 정했습니다. 학교별 제출본에 실제 학교명·대표번호를 넣는 것을 조건으로 충족할 수 있습니다.

ScoreLab 개발·배포자가 학생 데이터를 중앙 수집하지 않는 구조이므로, 실제 학교용 제출본에는 해당 학교·교육기관의 개인정보 보호책임자 또는 개인정보 담당부서와 ScoreLab 제품지원 연락처를 역할별로 구분해 기재해야 합니다.

### 5-2. 제3자 제공 정보가 기재되어 있는가? — 조건부 충족

정상적인 사용에서는 학생 개인정보를 제3자에게 제공하지 않는다고 안내되어 있고 코드상으로도 Gemini에는 학생 답안·점수·필기·화면 이탈 기록을 보내지 않습니다. AI 기능은 교사가 올린 시험지·정답지, 교과·학년군 및 성취기준 정보를 전송합니다.

조건:

- 개인정보가 없는 빈 시험지·정답지만 업로드해야 합니다.
- 현재 AI 업로드 화면에는 개인정보 포함 문서 업로드 금지 경고가 없습니다.
- 교사가 개인정보가 적힌 파일을 올리면 Google로 함께 전송될 수 있으므로 화면 경고와 학교 운영지침이 필요합니다.

판정 조건: 업로드 전 경고를 구현하고 “학생 개인정보 제3자 제공 없음”의 전제와 예외를 최종 안내서에 명시하면 충족 가능.

### 5-3. 개인정보 위·수탁관계가 기재되어 있는가? — 해당 없음

현재 구조에서는 ScoreLab 개발·배포자가 학생 데이터를 호스팅하거나 원격 처리하지 않고, 학생 데이터는 교사 PC에 저장됩니다. Gemini에도 정상 사용 시 학생 개인정보를 보내지 않으므로 학생 개인정보 처리위탁 관계는 확인되지 않습니다.

단, 향후 클라우드 동기화, 자동 오류보고, 원격지원, 중앙 계정·결제 또는 학생 데이터 서버 저장 기능을 추가하면 위·수탁 여부를 다시 검토해야 합니다. 학운위 제출자료에는 이러한 현재 구조와 재검토 조건을 명시해야 합니다.

## 3. 선택기준 점검

### 교육목표 및 학생 특성 적합성 — 충족 가능

시험 제작·실시·자동 채점, 문항별·성취기준별 분석과 피드백 기능은 수업·형성평가 목적과 직접 관련됩니다. 교사가 교과, 학년군, 제한시간, 문항과 성취기준을 설정할 수 있습니다.

학교별 증빙으로 실제 수업목표, 대상 학년, 활용 차시, 평가 방식과 기대 효과를 별도로 작성하면 됩니다.

### 콘텐츠 품질 및 안전성 — 조건부 충족

ScoreLab은 완성된 학습콘텐츠를 일괄 제공하기보다 교사가 시험 문항과 정답을 만들거나 업로드하는 도구입니다. AI 결과는 교사가 확인·수정할 수 있고 자동 반영 전에 검토할 수 있습니다.

다만 AI가 추출한 문항·정답·성취기준의 정확성을 보장하는 검증 절차, 연령 적합성 확인 책임, 오류 발생 시 수정 절차를 제출자료에 명문화해야 합니다. “검증된 AI 모델이므로 안전하다”는 설명만으로는 부족합니다.

### 사용 환경 적합성 — 부분 충족

장점:

- 학생은 별도 설치 없이 브라우저로 같은 LAN의 교사 PC에 접속합니다.
- 반응형 웹 UI이며 QR 접속 링크를 제공합니다.
- 인터넷이 없어도 기본 시험·채점 기능은 로컬 네트워크에서 사용할 수 있습니다. Gemini 기능만 외부 인터넷이 필요합니다.

한계:

- 교사 PC에 Node.js 22 이상이 별도로 필요합니다.
- 방화벽, 학교 AP의 기기간 통신 차단, 포트 4000 사용 가능 여부에 따라 접속이 실패할 수 있습니다.
- HTTPS가 아니며, iOS 등 일부 환경에서는 전체화면 감지 방식이 다릅니다.
- 지원 브라우저·OS·동시접속 인원·저사양 기기·네트워크 끊김에 대한 공식 시험 결과가 없습니다.

판정 조건: 학교 환경 호환성 시험표와 최소·권장 사양, 방화벽 안내, 지원 브라우저, 동시접속·복구 시험 결과가 필요.

### 접근성 및 사용성 — 부분 충족

로고 대체텍스트, 일부 입력 레이블, 키보드로 동작하는 기본 버튼 등 기초 요소는 있습니다. 다만 다음 증빙이 없습니다.

- 키보드만으로 전 과정 수행 시험
- 스크린리더와 초점 순서 시험
- 색상 대비 및 확대·고대비 모드 시험
- 교사 로그인 입력의 명시적 레이블
- 필기 캔버스의 대체 입력·설명
- 오류 메시지의 보조기술 알림

판정 조건: 접근성 자체점검표와 주요 문제 수정이 필요.

### 서비스 운영 및 지원체계 — 부분 충족

사용설명서는 마련되어 있고 제품지원은 개발자의 개인 이메일로 제공하기로 정했습니다. 실제 이메일 주소, 통상 응답시간, 장애 공지 경로와 버전별 변경내역 제공 방식은 제출본에 추가해야 합니다.

판정 조건: 공식 문의 채널, 사용자 매뉴얼, 설치·방화벽·백업·복구 안내, 장애 대응 기준, 업데이트·변경내역 제공 방식이 필요.

## 4. 제출 전 보완 우선순위

### P0 — 학운위 제출 전 반드시 완료

1. 학교별 제출본에 학교명·대표 전화번호와 개발자 지원 이메일 주소 기재
2. 권리행사 본인확인, 처리기한과 결과 통지 방법 확정
3. 이미지·로그·백업 파일의 보유기간과 파기 절차 확정
4. 학생 통신의 HTTPS 적용 또는 학교가 수용할 수 있는 동등한 전송구간 보호대책 마련
5. 비밀번호 최소 기준 강화, 로그인 시도 제한, 최초 비밀번호 설정 보호
6. 실제 설치 환경에서 학생 안내와 완전삭제 기능 검증

### P1 — 보안성과 심의 통과 가능성을 크게 높임

1. 학생 단위 전체 기록 조회·정정·완전삭제 기능
2. 시험 영구 삭제 시 업로드 이미지 동시 삭제
3. `.bak`·로그 자동 정리와 백업 암호화 또는 암호화 저장 안내
4. CORS 및 Socket.IO origin·교사 인증 제한
5. Gemini 업로드 전 개인정보 포함 금지 경고
6. `xlsx` 고위험 취약점 제거 또는 대체 라이브러리 도입
7. API 키 삭제 기능과 브라우저 로컬 데이터 초기화 기능

### P2 — 선택기준 증빙 강화

1. Windows·Chrome·Edge·Android·iOS 호환성 시험
2. 학급 규모별 동시접속 및 네트워크 복구 시험
3. 키보드·스크린리더·색상 대비 접근성 시험
4. AI 추출 결과 교사 검토 절차와 오류 수정 안내
5. 버전 정책, 장애 대응, 지원 범위와 변경이력 문서화

## 5. 실행 확인 결과

- `npm run build`: 성공
- `npm run lint -w client`: 오류 0건, React 관련 경고 9건
- 루트 `npm audit --omit=dev`: high 1건(`xlsx`)
- Electron `npm audit --omit=dev`: 취약점 0건

빌드 성공은 기능 실행 가능성을 보여주지만, 개인정보 필수기준이나 학교 환경 호환성을 증명하지는 않습니다. 실제 학운위 제출에는 위 보완사항과 학교 환경 시험 결과가 필요합니다.
