# ScoreLab 학습지원 소프트웨어 선정기준 점검

> 점검일: 2026-09-21
> 기준 버전: ScoreLab 2.0.1
> 기준 문서: `학교용 필수기준체크리스트 예시.pdf`
> 점검 범위: 현재 클라이언트·서버·Electron 코드와 `docs/legal` 문서

## 1. 제품과 개인정보 처리관계

ScoreLab은 학교 교육과정 운영을 지원하고 학생의 시험 참여·답안·점수 등을 처리하므로 학습지원 소프트웨어 선정 검토 대상에 해당할 가능성이 높습니다.

학생 데이터는 교사 PC에 저장되고 개발자의 중앙 서버로 전송되지 않습니다. 따라서 역할은 다음과 같이 구분합니다.

| 주체 | 역할 |
|---|---|
| 사용 학교 | 학생 정보의 개인정보처리자, 사용 승인·보유기간·권리행사·삭제 절차 결정 |
| 담당 교사 | 학교의 관리·감독 아래 시험 운영과 데이터 조회·정정·삭제 수행 |
| 학교장 | 학교의 개인정보 보호책임자 |
| 학교 과학정보부 | 개인정보 보호와 권리행사 실무 지원 |
| ScoreLab 개발자 | 프로그램 제공과 제품 기술지원. 학생 데이터를 수집·호스팅·원격 열람하지 않음 |
| Google Gemini | 교사가 선택한 빈 시험지·정답지 분석. 정상 사용 시 학생 개인정보를 받지 않음 |

## 2. 종합 판정

현재 ScoreLab은 로컬 저장, 개발자 미수집, 교사기능 localhost 제한, 무작위 학생 토큰, 전체·선택 학생 및 학년도별 삭제기능과 학생 안내를 갖추고 있습니다. 학생 접속은 교사가 선택한 네트워크의 같은 서브넷으로 제한됩니다.

다만 최종 제출 전 다음 항목을 보완하거나 학교의 운영조치로 명확히 수용해야 합니다.

1. 학생 기기와 교사 PC 간 HTTP 통신
2. 교사 비밀번호 최소 4자 및 로그인 실패 제한 없음
3. 로그·복원 사본·일부 이미지의 보관·삭제를 사용 교사 또는 학교가 직접 관리해야 함
4. 내보낸 백업 파일의 자체 암호화 없음
5. `xlsx` 직접 의존성의 알려진 high 취약점
6. 학교별 실제 학교명·대표번호·공식 문의 경로 미기재

## 3. 필수기준 점검

### 3.1 개인정보 최소처리 — 부분 충족

확인된 사항:

- 학생 회원가입, 이메일, 전화번호, 주소와 광고 식별자를 요구하지 않음
- 번호만 필수이고 이름은 선택항목
- 접속 IP와 User-Agent를 DB에 별도 저장하지 않음
- 개발자 서버 또는 외부 클라우드에 학생 데이터를 저장하지 않음

운영 조건:

- 가능하면 이름 없이 번호만 사용
- 주관식 답안에 이름·연락처 등을 적지 않도록 안내
- 필기, 문항별 시간과 화면 이탈 기록의 교육상 필요성을 수업계획에 명시

### 3.2 처리 목적의 안내 — 충족 가능

데이터 처리 안내서에 시험 진행, 채점, 감독, 분석과 학습 피드백 목적이 항목별로 기재되어 있습니다. 학생 시험 시작 화면에도 처리 항목과 목적을 안내합니다.

학교는 실제 수업의 대상·목표·평가 방식과 담당자를 학교별 선정자료에 추가해야 합니다.

### 3.3 처리 항목과 보유기간 — 부분 충족

학생 학습 데이터의 보유기간은 해당 학기 말까지로 정했고 전체·선택 학생 및 학년도별 완전삭제 기능을 구현했습니다.

남은 사항:

- 시험 이미지·서버 로그·복원용 `.bak` 파일을 사용 교사 또는 학교가 직접 보관·점검·삭제
- 교사가 내보낸 백업의 보관 장소와 파기 여부를 사용 교사 또는 학교가 직접 관리
- 학생 브라우저의 사이트 데이터 삭제 안내

### 3.4 안전성 확보조치 — 부분 충족

구현된 조치:

- 학생 데이터의 교사 PC 로컬 저장
- scrypt 비밀번호 해시
- 12시간 만료 HttpOnly·SameSite=Lax 교사 세션 쿠키
- 교사 로그인·세션 발급·관리 API와 교사 화면의 localhost 제한
- 학생별 무작위 접근 토큰
- Gemini API 키의 AES-256-GCM 암호화 저장
- 인증된 교사만 시험·명단·백업·설정 관리 가능
- 업로드 형식과 파일크기 제한

남은 위험:

- 학생 LAN 통신은 HTTP이며 HTTPS가 아님
- SQLite DB와 내보낸 백업은 자체 암호화되지 않음
- 비밀번호 최소 길이가 4자이고 로그인 실패 횟수 제한이 없음
- CORS와 Socket.IO 접근범위 추가 제한 필요
- 로그 자동 순환 없음
- `xlsx` 라이브러리 high 취약점 조치 필요

학교 운영 보완조치:

- 교사가 선택한 학교 관리 내부망의 같은 서브넷에서만 학생 접속 허용
- 교사 PC 계정·방화벽·저장장치 보호
- 시험 주소와 QR을 수업 참여자에게만 제공
- 배포 전 실제 학교 네트워크에서 접속·복구·삭제 시험

### 3.5 열람·정정·삭제·처리정지 — 부분 충족

- 1차 요청 창구: ScoreLab을 사용한 담당 교사
- 지원 부서: 학교 과학정보부
- 본인·보호자 확인: 학급 명단과 학교의 보호자 확인 절차 이용
- 삭제: 학생 관리 화면에서 전체 또는 원하는 학생을 선택해 모든 학습 데이터 삭제 가능

학교별로 처리기한, 결과 통지 방법과 요청이 제한될 수 있는 사유를 확정해야 합니다.

### 3.6 만 14세 미만 학생 보호 — 부분 충족

- 학생 회원가입이 없음
- 시험 시작 전에 처리 항목·목적·보유기간·화면 이탈 규칙과 담당 교사 문의 방법을 안내
- 이름을 입력하지 않고 번호만 사용할 수 있음

학교는 교육활동의 처리 근거를 확인해야 하며, 동의를 근거로 별도의 선택처리를 추가한다면 법정대리인 동의와 기록 절차를 마련해야 합니다.

### 3.7 개인정보 보호책임자와 문의처 — 조건부 충족

- 개인정보처리자: ScoreLab을 사용하는 학교
- 개인정보 보호책임자: 학교장
- 실무 담당부서: 과학정보부
- 권리행사 1차 접수: 담당 교사
- 연락처: 학교 대표번호

학교별 제출본에 실제 학교명·대표번호·공식 문의 경로를 넣어야 합니다. 개발자 제품지원 이메일은 학생 데이터 요청 창구와 분리하여 표시합니다.

### 3.8 제3자 제공 — 조건부 충족

학생 데이터는 외부로 제공되지 않습니다. Gemini에는 교사가 선택한 빈 시험지·정답지, 교과·학년군과 성취기준 정보만 전송됩니다.

개인정보가 포함된 파일을 업로드하지 않도록 교사 안내와 화면 경고가 필요합니다. 개인정보 포함 자료를 실제로 업로드하려는 경우에는 별도의 제공·위탁·국외 이전 검토가 필요합니다.

### 3.9 개인정보 처리위탁 — 현재 해당 없음

개발자는 학생 데이터를 호스팅하거나 원격 처리하지 않습니다. 정상 사용 시 Gemini에도 학생 개인정보가 전송되지 않으므로 현재 확인되는 학생 개인정보 처리위탁 관계는 없습니다.

클라우드 동기화, 자동 오류보고, 원격지원 또는 학생 데이터 서버 저장 기능을 추가하면 재검토해야 합니다.

## 4. 선택기준 점검

### 교육목표와 학생 특성 적합성 — 충족 가능

시험 작성·실시·채점과 문항·성취기준별 분석은 수업·평가와 직접 관련됩니다. 학교는 대상 학년, 교과, 활용 차시, 수업목표와 기대효과를 추가합니다.

### 콘텐츠 품질과 안전성 — 조건부 충족

교사가 문항·정답을 최종 확정하며 AI 결과를 수정할 수 있습니다. AI 결과의 정확성, 연령 적합성과 저작권을 교사가 확인하는 절차를 명시해야 합니다.

### 사용환경 적합성 — 부분 충족

- 학생은 별도 설치 없이 같은 LAN에서 브라우저 접속
- 기본 시험 기능은 외부 인터넷 없이 사용 가능
- Gemini 기능만 외부 인터넷 필요

학교 AP의 기기간 통신, 방화벽 포트 4000, 지원 OS·브라우저, 동시접속 인원과 네트워크 복구를 실제 환경에서 시험해야 합니다.

### 접근성과 사용성 — 부분 충족

기본 레이블과 키보드 버튼은 있으나 스크린리더, 초점 순서, 색상 대비, 확대 및 필기 대체수단에 대한 공식 시험자료가 없습니다.

### 운영과 지원체계 — 부분 충족

사용설명서는 프로그램 하단의 `사용설명서` 팝업과 저장소 문서로 마련되어 있습니다. 제품지원은 `isaacksh0101@sen.go.kr`에서 평일 기준 7일 이내 답변을 목표로 하며, 변경내역과 장애 정보는 ScoreLab GitHub 저장소에 게시합니다.

## 6. 배포 전 개발자가 완료할 항목

### 우선순위 높음

1. 교사 비밀번호 기준 강화와 로그인 시도 제한
2. `xlsx` 취약점 제거 또는 대체
3. Gemini 업로드 전 개인정보 포함 금지 경고
4. 로그·이미지·복원 사본의 수동 보관·삭제 절차를 사용설명서에 기재

### 품질 증빙

1. Windows·Chrome·Edge·Android·iOS 호환성 시험
2. 학급 규모별 동시접속과 네트워크 단절 복구 시험
3. 키보드·스크린리더·색상 대비 접근성 시험
4. 설치·방화벽·백업·복원·삭제 설명서 정리
5. GitHub 저장소에서 버전별 변경이력과 장애 공지 관리

## 7. 최근 확인 결과

- 프론트엔드 프로덕션 빌드: 성공
- 클라이언트 린트: 오류 0건, 기존 React 경고 있음
- 서버 접근통제 단위 확인: localhost 허용, LAN 교사 접근 403 차단
- 루트 `npm audit --omit=dev`: `xlsx` 관련 high 1건
- Electron `npm audit --omit=dev`: 취약점 0건

빌드 성공은 개인정보 기준이나 학교 환경 적합성을 자동으로 증명하지 않습니다. 실제 제출본에는 학교별 운영사항과 환경 시험 결과를 함께 첨부해야 합니다.
