# 수업 설계 도구 · 디자인 취향 가이드

> 출처: [Leonxlnx/taste-skill](https://github.com/Leonxlnx/taste-skill) (MIT)의 anti-slop 원칙을 이 프로젝트에 맞게 재해석함.
> **중요한 차이:** taste-skill 원문은 랜딩페이지·포트폴리오용이며 "대시보드, 멀티스텝 폼/마법사에는 안 맞는다"고 스스로 밝힌다. 이 프로그램(`수업설계도구.html`)은 정확히 그 멀티스텝 폼/마법사형 업무 도구이므로, 원문의 레이아웃·모션 처방(스크롤 하이재킹, bento grid, 마퀴, GSAP 스크롤텔링 등)은 **가져오지 않는다.** 가져오는 것은 그 아래에 깔린 "제네릭 AI 티를 벗긴다"는 태도와, 타이포·색·상태·카피에 대한 구체적 규율이다.

## 0. 이 프로젝트가 무엇인지 (모든 규칙의 전제)

- **오프라인 단일 HTML 파일.** 서버·빌드 도구·npm 패키지·외부 CDN(폰트, 아이콘, JS 라이브러리)이 없다. 학교 공용 컴퓨터에서 인터넷 없이도 열려야 한다. → 폰트는 시스템 폰트만, 아이콘은 인라인 SVG만, 애니메이션은 순수 CSS/바닐라 JS만.
- **사용자는 초등학교 교사 한 명.** 방문객을 설득하는 마케팅 페이지가 아니라, 매일 붙잡고 앉아 문서를 채우는 **업무 도구**다. "인상적"보다 "믿을 만하고 조용함"이 맞는 톤이다.
- **화면 구조는 폼·마법사형이다.** 왼쪽 단계 목록 + 가운데 카드형 입력/편집 영역 + 하단 확정 바. 이 구조 자체를 갈아엎지 않는다 (기존 CLAUDE 지침: 이미 만든 것을 갈아엎지 말고 이어서 만든다).
- **한국어 UI.** 타이포 규칙은 라틴 문자 전용 트릭(자간 좁히기, 세리프 디스플레이 폰트 로테이션 등)을 그대로 가져오지 않는다.

## 1. 절대 하지 않는 것 (Anti-Slop 체크리스트)

이 프로그램에서 아래 패턴이 보이면 고친다.

- **이모지를 아이콘으로 쓰지 않는다.** 지금 헤더에 있는 💾 📂 ⚙ ↺ 같은 이모지 아이콘은 임시방편이며, 발견 즉시 [3. 아이콘] 규칙에 따라 인라인 SVG로 교체 대상이다. 이모지는 렌더링이 OS마다 다르고 장난감 같은 인상을 준다.
- **"AI 보라색/파란색 그라디언트"를 쓰지 않는다.** 배경이나 버튼에 보라-파랑 계열 그라디언트를 기본값으로 깔지 않는다. 이 프로젝트는 이미 단일 액센트(`--accent`, 파란 계열)를 쓰고 있다 — 그걸로 충분하다. 두 번째 액센트 색을 추가하지 않는다.
- **순수 검정/순수 흰색을 배경으로 쓰지 않는다.** `#000000`, `#ffffff`를 그대로 큰 배경에 쓰지 않는다 (이미 `--bg`, `--panel`이 이 규칙을 지키고 있다. 새 화면에서도 이 변수를 그대로 쓴다).
- **채도 과한 강조색을 쓰지 않는다.** 새 상태색(성공/경고/위험)을 추가해야 하면 기존 `--good`/`--warn`/`--danger` 팔레트의 채도·명도 톤에 맞춘다. 쨍한 원색을 섞지 않는다.
- **3열 균등 카드로 정보를 나열하지 않는다.** "성취기준 3개를 카드 3개로" 같은 균등 그리드 나열은 이 앱에서 정보 구조를 숨긴다. 지금처럼 목록/표/그룹(`subject-group`) 형태를 우선한다.
- **모서리 반경을 섞지 않는다 (SHAPE CONSISTENCY LOCK).** 이 프로젝트는 이미 카드 `var(--radius)`(10px), 토글 버튼은 pill(`20px`), 배지는 원형이라는 규칙이 있다. 새 컴포넌트를 만들 때 이 세 갈래 중 하나를 골라 쓰고, 네 번째 반경 값을 새로 만들지 않는다.
- **AI 카피 클리셰를 쓰지 않는다.** "혁신적인", "손쉽게", "한 번에 끝내는", "차세대" 같은 과장된 수식어를 넣지 않는다. 지금 화면의 문구들처럼 담백하고 구체적인 한국어를 쓴다 ("성취기준을 1개 이상 골라주세요"처럼 무엇을 해야 하는지 바로 말한다).
- **엠대시(—)를 쓰지 않는다.** 한국어 문장에서도 영문 em-dash를 문장 구분자로 쓰지 않는다. 쉼표, 마침표, 중점(·, 이미 이 앱이 상태줄에 쓰고 있음)으로 대체한다. 중점(·)은 한 줄에 과하게 반복하지 않는다.
- **placeholder를 label 대신 쓰지 않는다.** 입력칸에는 반드시 `<label>`이 있어야 하고, placeholder는 예시 텍스트로만 쓴다 (이미 잘 지키고 있다 — 계속 유지).
- **정적 상태만 만들지 않는다.** 버튼/입력 하나를 새로 만들 때 기본·hover·disabled·(필요하면 loading/error) 상태를 같이 정의한다. "성공 화면만 만들고 실패는 나중에"는 금지.

## 2. 색 · 다크모드

- 이 프로젝트의 팔레트는 이미 `:root`와 `@media (prefers-color-scheme: dark)`에 고정돼 있다. **새 화면을 만들 때 새 색상 값을 하드코딩하지 말고 반드시 아래 변수를 재사용한다.**

  | 변수 | 라이트 | 다크 | 용도 |
  |---|---|---|---|
  | `--bg` | `#f5f6f8` | `#14171f` | 페이지 배경 |
  | `--panel` | `#ffffff` | `#1c202b` | 카드/입력 배경 |
  | `--ink` / `--ink-soft` | `#1f2430` / `#5b6270` | `#e7e9ee` / `#9aa0ad` | 본문 / 보조 텍스트 |
  | `--line` | `#e2e5ea` | `#2c3140` | 테두리 |
  | `--accent` / `--accent-soft` / `--accent-ink` | `#2f6fed` / `#eaf1ff` / `#14418f` | `#5c8cff` / `#202b45` / `#a9c3ff` | 유일한 강조색 (파란 계열) |
  | `--good` / `--warn` / `--danger` (+ `-soft`) | 초록 / 황토 / 빨강 | 톤 유지 | 확정·주의·오류 |
  | `--sidebar-bg` / `--sidebar-ink` / `--sidebar-ink-dim` | `#1c2333` 계열 | `#10131b` 계열 | 왼쪽 단계 목록 (항상 어두운 배경, 라이트/다크 모드와 무관) |

- **한 화면에 강조색은 하나.** `--accent`가 이미 "선택됨/확정 가능" 의미를 가지고 있다. 새 기능에서 두 번째 파란 계열이나 다른 색으로 "선택됨"을 표현하지 않는다.
- **다크모드는 옵션이 아니라 기본.** 새 컴포넌트를 추가하면 반드시 라이트/다크 두 모드에서 대비를 확인한다. 한쪽만 보고 끝내지 않는다.
- **사이드바는 페이지 테마와 별개로 항상 어둡다.** 지금 구조(라이트 페이지 + 어두운 사이드바)를 유지한다. 페이지가 다크모드가 됐다고 사이드바를 더 밝게 바꾸지 않는다.

## 3. 아이콘

- CDN 아이콘 폰트나 아이콘 라이브러리는 오프라인 제약상 쓸 수 없다. **인라인 `<svg>`만 쓴다.**
- 이모지(💾 📂 ⚙ 등)를 발견하면 다음 스펙의 인라인 SVG로 교체한다: `viewBox="0 0 24 24"`, `stroke="currentColor"`, `stroke-width="1.75"`, `fill="none"`, `stroke-linecap="round"`, `stroke-linejoin="round"`. 24×24 그리드, 단순한 기하학적 형태(선 아이콘) 하나로 통일한다.
- **한 프로젝트에 한 스타일.** 선 두께(`stroke-width`)와 그리드 크기를 모든 아이콘에서 동일하게 맞춘다. 어떤 아이콘은 채워진(fill) 스타일, 어떤 아이콘은 선(stroke) 스타일을 섞지 않는다.
- 아이콘만으로 의미가 불분명한 버튼(저장/불러오기/설정/초기화 등)은 아이콘 옆에 짧은 한글 라벨을 반드시 같이 둔다 (지금처럼 "💾 저장" → "[저장 아이콘] 저장").

## 4. 타이포그래피 (한글)

- 폰트는 시스템 스택만 쓴다: `"Apple SD Gothic Neo", "Malgun Gothic", "Segoe UI", sans-serif` (이미 적용됨). 웹폰트를 CDN에서 받아오지 않는다 — 오프라인에서 깨진다.
- 라틴 문자 전용 트릭(자간 `-0.02em` 좁히기, 세리프 디스플레이 폰트, 이탤릭 강조)은 한글에 그대로 적용하지 않는다. 한글은 자간을 좁히면 가독성이 떨어진다. 강조는 **굵기(700)**와 **색(`--accent-ink`, `--danger`)**으로 표현하고, 이탤릭·자간은 쓰지 않는다.
- 본문 줄간격은 넉넉하게 (`line-height: 1.5~1.6`, 이미 `body { line-height: 1.55 }`). 긴 안내문(`card-desc`, `hint`)일수록 줄간격을 줄이지 않는다.
- 위계는 **크기 2~3단계 + 굵기 2단계**로 충분하다 (`h2` 15.5px/700, 본문 15px/400, 보조 12.5~13px/400). 새로운 크기 값을 계속 추가하지 않는다.

## 5. 레이아웃 · 상태 · 모션 (마법사형 도구 기준)

taste-skill 원문의 "VARIANCE(비대칭 실험)"는 이 도구에는 적용하지 않는다. 교사가 서식을 채우는 도구에서 비대칭·예측 불가능한 배치는 사용성을 해친다. 대신 이렇게 고정한다.

- **레이아웃 변주(VARIANCE)는 낮게 유지.** 카드 세로 쌓기 + 좌측 라벨/우측 입력 또는 상단 라벨/하단 입력, 두 패턴만 쓴다. 새 화면마다 다른 그리드 구조를 실험하지 않는다.
- **정보 밀도(DENSITY)는 중간.** 성취기준처럼 항목이 많은 목록은 지금처럼 그룹(교과별) + 표 형태 행으로 묶는다 (10줄 넘는 목록을 카드 그리드로 흩뿌리지 않는다 — 스캔하기 어려워진다).
- **모션(MOTION)은 최소, 목적이 있을 때만.**
  - 허용: 상태 전환 시 배경/테두리 색 전이 (`transition` 150~250ms), disabled ↔ enabled 전환, hover 시 미세한 배경색 변화.
  - 금지: 스크롤 연동 애니메이션, 패럴랙스, 무한 반복 모션, 마퀴, 자동 캐러셀. 이 도구는 스크롤해서 감상하는 페이지가 아니라 채워 넣는 서식이다.
  - `prefers-reduced-motion: reduce`가 켜져 있으면 전이 시간을 0에 가깝게 줄인다.
- **상태는 항상 4종 세트로 만든다.** 새 인터랙션 요소(버튼, 토글, 입력)를 추가할 때 기본 / hover / disabled / (해당되면) 에러 네 가지를 한 번에 정의한다. 지금 `.btn[disabled]`, `.toggle-btn[disabled]` 패턴을 그대로 따른다.
- **포커스 링을 지우지 않는다.** 키보드 탐색을 위해 `outline`을 임의로 `none`으로 죽이지 않는다. 커스텀 포커스 스타일을 넣더라도 시각적으로 명확해야 한다.
- **버튼 대비를 항상 확인한다.** 새 버튼을 만들 때 배경색 대비 글자색이 WCAG AA(본문 4.5:1) 이상인지 확인한다. 특히 `--accent` 위에 흰 글자, `--danger-soft` 위에 `--danger` 글자 같은 기존 조합을 벗어날 때 주의한다.

## 6. 카피 (문구) 규율

- **명령형·구체형으로 쓴다.** "무엇이 문제인지"와 "무엇을 하면 되는지"를 한 문장에 담는다. 지금의 `missingRequirements()` 문구들("학년군을 골라주세요", "성취기준을 1개 이상 골라주세요")이 좋은 예다. 이 톤을 계속 따른다.
- **에러 메시지는 원인을 구분해서 알린다.** "오류가 발생했습니다" 한 줄로 뭉뚱그리지 않는다. (이미 AI 연동 에러를 키/모델/한도/네트워크로 구분한 것처럼, 앞으로 추가하는 모든 실패 케이스도 원인별로 나눈다.)
- **과장된 성공 문구를 쓰지 않는다.** 느낌표·감탄사("완벽해요!", "대단해요!")를 쓰지 않는다. 담담하게 사실만 말한다 ("확정되었습니다").
- **placeholder/예시 문장은 실제로 쓸 법한 한국어로 채운다.** "예: 4학년", "예: 23명, 활동적이고..." 처럼 구체적인 예시를 유지한다. "예: 텍스트 입력" 같은 의미 없는 placeholder는 쓰지 않는다.

## 7. 매 수정 전 프리플라이트 (Redesign 체크리스트)

`수업설계도구.html`을 고치거나 새 단계(3~6단계)를 붙이기 전, 아래를 훑는다. taste-skill의 redesign-skill 감사 순서를 이 프로젝트 규모에 맞게 줄인 버전이다.

1. 새 색상 값을 하드코딩했는가? → [2. 색] 변수로 교체.
2. 새 모서리 반경 값을 만들었는가? → 기존 3갈래(카드/pill/원형) 중 하나로 교체.
3. 이모지를 아이콘으로 썼는가? → [3. 아이콘] 인라인 SVG로 교체.
4. 버튼/입력에 disabled·hover 상태가 빠졌는가? → 추가.
5. 다크모드에서 대비를 확인했는가? (라이트만 보고 끝내지 않았는가)
6. 새 문구에 클리셰·엠대시·느낌표가 있는가? → [6. 카피] 규칙대로 재작성.
7. 스크롤 애니메이션·자동 반복 모션을 추가했는가? → 이 도구엔 불필요, 제거.
8. 포커스 링이나 키보드 접근성을 해치는 `outline: none`을 넣었는가? → 제거.

비대칭 히어로, bento grid, GSAP 스크롤 하이재킹/스티키 스택, 마퀴, 매그네틱 버튼, glassmorphism, 세리프 디스플레이 폰트 로테이션, 3개 아이콘 라이브러리 우선순위표. 이후 랜딩페이지성 결과물(예: 학부모 공개용 요약 페이지 등)을 이 프로젝트 밖에서 만들 일이 생기면, 그때는 이 파일이 아니라 taste-skill 원문(`skills/taste-skill/SKILL.md`)을 직접 참고한다.
